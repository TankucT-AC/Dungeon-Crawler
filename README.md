# 🎮 Dungeon-Crawler: 2D Roguelike-платформер на SFML

Добро пожаловать в **Dungeon-Crawler** — игру в жанре roguelike с видом сверху, где вы исследуете процедурно генерируемые подземелья, сражаетесь с врагами и стараетесь выжить как можно дольше. Проект написан на C++17 (игра) / C++20 (сервер) с использованием SFML и Qt6 и демонстрирует продвинутую модульную архитектуру (нет).

---

## 🧩 Особенности

- **Процедурная генерация** подземелий с настраиваемым `DungeonConfig` (размер, комнаты, коридоры)
- **Три биома**: default, desert, winter — со своими стенами, полом и сундуками
- **Волны врагов**, зачистка комнат, портал в следующий раунд (всего 3 раунда, дальше — чистилище)
- **Гибкая система сущностей**: игрок, враги, пули, стены
- **Сменное оружие**: пистолет, винтовка, ПП (два слота) с перезарядкой и расчётом попаданий
- **Коллизии** на основе ограничивающих прямоугольников (AABB)
- **Динамическая загрузка ресурсов** через ResourceManager (можно было и через enum и массивы в compile-time, но я говнокодер, сори)
- **Авторизация** через Qt6-окно: регистрация с автогенерацией пароля, логин, 2FA через TOTP с QR-кодом
- **HTTPS-сервер** на Drogon + SQLite: регистрация, логин, выдача и проверка TOTP

## 🧠 Ключевые компоненты

### 🚀 Ядро (`Engine`)
Центральный класс, который управляет главным игровым циклом, обновлением всех сущностей, отрисовкой и обработкой событий. Инициализирует окно SFML, загружает текстуры и запускает игру. Делегирует логику менеджерам:
- `CombatManager` — волны врагов, закрытие/открытие врат, зачёт зачистки;
- `RoundManager` — генерация раундов, портал, чистилище после 3-го раунда;
- `PickupManager` — подбор оружия и сундуки с дропом;
- `PhysicsManager` — движение и коллизии;
- `InputManager` — клавиатура/мышь;
- `RenderManager` — отложенная отрисовка с Y-сортировкой;
- `LevelMap` — карта уровня: комнаты, коридоры, врата.

### 🤺 Игрок (`Player`)
Наследуется от `Entity`. Имеет:
- перемещение с помощью клавиш (WASD/стрелки)
- систему стрельбы с задержкой (`ShootDelay`)
- уменьшенный хитбокс для более честных попаданий
- метод `cooldown()` для сброса таймера после выстрела

### 👾 Противники (`Enemy`)
Также наследуются от `Entity`:
- движутся по направлению к игроку
- имеют здоровье и получают урон
- проверяют столкновение с пулями игрока
- уничтожаются при нулевом здоровье

### 🔨 Генератор подземелий (`DungeonGenerator`)
Ключевой модуль процедурной генерации:
- строит `DungeonData` по настраиваемому `DungeonConfig` (`defaultConfig()`)
- расставляет комнаты, коридоры, точки спавна игрока/врагов, сундуки и портал
- результат уходит в `LevelMap` через `buildFromData()` с темой биома (`BiomeTheme`)

### 🏠 Комнаты (`Room`)
- Содержат стены (`Wall`), врата (`Gate`), сундуки (`Chest`), портал (`Portal`)
- Знают свои точки спавна и состояние боя (зачищена или нет)
- Участвуют в отрисовке и обновлении всех своих элементов

### 🧱 Стены (`Wall`)
- Неподвижные объекты, создаваемые внутри комнат
- Участвуют в коллизиях – не дают игроку и врагам проходить сквозь них

### 💥 Пули (`Bullet`)
- Автоматически летят в заданном направлении
- Ограничены временем жизни (`lifetime`)
- Наносят урон врагам при попадании
- Могут быть деактивированы (`setBulletAlive`)

### 📦 Менеджер ресурсов (`ResourceManager`)
- Кеширует загруженные текстуры для избежания повторной загрузки
- Единственная точка получения графических ресурсов

### 🔐 Авторизация (`src/network`)
- `AuthClient` — синхронный клиент протокола (`login`/`register`/`setup_2fa`/`verify_2fa`), транспорт на `QNetworkAccessManager` (подменяется фейком в тестах)
- `AuthConfig` — хост/порт/пути/таймауты в одном месте, переопределяются через `2DGAME_AUTH_*`
- `AuthDialog` — Qt Widgets-окно: логин, регистрация, показ сгенерированного пароля, QR для 2FA
- `AppOptions` — флаги запуска `--no-auth` / `--debug-collisions` (и env `2DGAME_NO_AUTH` / `2DGAME_DEBUG_COLLISIONS`)

### 🖥️ Сервер (`server/`, Drogon)
- `AuthController` — `POST /api/register`, `/api/login`, `/api/setup_2fa`, `/api/verify_2fa`
- `DatabaseManager` — SQLite (`users.db` рядом с бинарником): хэши паролей (PBKDF2-HMAC-SHA256), TOTP-секреты
- `TOTPGenerator` — пароли, секреты, коды TOTP (HMAC-SHA1)

## ⚙️ Зависимости

- **SFML 2.6** — графика, ввод и окна игры.
- **Qt6** (Core/Widgets/Network) — окно авторизации и HTTPS-клиент.
- **Drogon 1.9.x** — HTTP(S)-сервер (подтягивается сам через FetchContent, ставить не надо).
- **OpenSSL** — TLS и криптография (пароли, TOTP).
- **SQLite3**, **jsoncpp** — база и JSON сервера.
- **C++17** (игра) / **C++20** (сервер), **CMake ≥ 3.20**, **Ninja**.

Установка зависимостей на Ubuntu/Debian:

```bash
sudo apt install libsfml-dev qt6-base-dev libssl-dev \
     libsqlite3-dev libjsoncpp-dev cmake ninja-build g++
```

На Windows проще всего использовать пакет через vcpkg.

## 🔧 Сборка и запуск

Сборка через пресеты (бинарники падают в `out/<пресет>/`):

```bash
git clone <ваш-репозиторий>
cd <project-folder>
cmake --preset gcc-debug
cmake --build out/gcc-debug
```

- Игра: `out/gcc-debug/game`
- Сервер: `out/gcc-debug/server/server`
- Только игра без сервера: `cmake --preset gcc-debug -DBUILD_SERVER=OFF`

Флаги игры:

| Флаг / env | Эффект |
|---|---|
| `--no-auth` / `2DGAME_NO_AUTH=1` | пропустить окно авторизации (для тестов без регистрации) |
| `--debug-collisions` / `2DGAME_DEBUG_COLLISIONS=1` | рисовать хитбоксы |

Тесты:

```bash
cd out/gcc-debug && ctest --output-on-failure
```

## 🖥️ Сервер авторизации

Сервер можно запускать из любого каталога: рабочие пути резолвятся от места бинарника.

```bash
./out/gcc-debug/server/server
```

- Конфиг `config.json` копируется рядом с бинарником при сборке, переопределение — через `DROGON_CONFIG=/путь/к/config.json`.
- Самоподписанный сертификат (`cert.pem`/`key.pem`, CN/SAN `127.0.0.1`) генерируется сборкой автоматически.
- База `users.db` создаётся рядом с бинарником при первом запуске.
- HTTPS по умолчанию на `127.0.0.1:8080`; клиент ходит туда же (см. `AuthConfig`, переопределяется через `2DGAME_AUTH_HOST`/`2DGAME_AUTH_PORT`).
